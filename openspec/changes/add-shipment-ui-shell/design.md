## Context

Рабочий проект: /Users/gorushkin/Work/ShipmentBuilder. React, Tailwind, shadcn/base-vega, Base UI и mobx-react-lite установлены. App содержит демонстрационную кнопку. ShipmentStore предоставляет исходный заказ, контейнеры, итоги, остатки и прогресс. ТМ в моках отсутствуют.

Приоритет структуры — первый эскиз пользователя (SCR-20260920-sbti.png). Второй (вариант 1.png) служит только ориентиром цветов и аккуратного оформления; его четырёхколоночную схему не переносим.

## Goals / Non-Goals

**Goals:** весь каркас с реальными данными, светлая компактная стилистика, синий акцент, Grid и предсказуемая прокрутка.

**Non-Goals:** выбор заказа/строк, раскрытие содержимого, сортировка пользователем, рабочие фильтры, создание ТМ, переносы, КМ/КА, сканирование и горячие клавиши, API, сохранение, обмен и печать. Новые тесты не добавляем.

## Decisions

### Сетка страницы

Страница занимает 100dvh. Основные строки: auto auto auto minmax(0, 1fr) auto — заголовок с действиями, сводка, подсказка, центральные панели, остатки. Высота служебных блоков определяется содержимым, а не жёсткими пикселями.

Центральная сетка: minmax(0, 1fr) auto minmax(0, 1fr). Средняя колонка компактная, содержит пять кнопок переноса/возврата. Каждая боковая панель также grid с областью управления auto и содержимым minmax(0, 1fr). По всей цепочке растягиваемых контейнеров задать min-height: 0 и min-width: 0. Прокрутка внутри каждой таблицы независимая, заголовки таблиц sticky. Не превращать таблицу в набор div: сохранить table/thead/tbody и заголовки столбцов.

Компоновку страницы, сводок и панелей делаем Grid, без flex-layout. Внутренняя реализация готовых UI-примитивов не требует переписывания. Приоритет — ноутбук/монитор; контрольные размеры 1440×900 и 1280×720. На узких окнах допускается безопасная горизонтальная прокрутка рабочего пространства вместо сжатия нечитаемых таблиц; отдельная мобильная компоновка отложена. При экстремально малой высоте/масштабировании содержимое должно оставаться доступным через прокрутку, без обрезания управления.

### Состав экрана

Заголовок «Формирование транспортных мест». Действия первого эскиза: получить SSCC, получить маркировки, отправка ТМ в 1С, повторная отправка, печать этикетки ТМ, печать паллетной этикетки, печать маркировок, повторная печать. Разместить компактной сеткой, все disabled.

Сводка: номер заказа, клиент, количество контейнеров и SKU, штуки, короба, кг, м³, прогресс с числовой подписью. Подсказка нейтральная: «Заказ проверен. Товары ожидают распределения»; не приглашать к отключённым действиям или сканированию.

Слева заголовок «К распределению», отключённый режим «Контейнеры / Товары» (выбраны контейнеры), подписи «Контейнер: —», «Товар: —». Таблица: Контейнер, SKU, ШТ, Короба, Объём. Контейнеры по номеру, без выделения и клика.

В центре disabled-кнопки: «Переместить строку», «Переместить всё по фильтру», «Переместить количество», «Вернуть строку», «Вернуть всё по фильтру»; направление обозначено иконкой и текстом.

Справа заголовок «Транспортные места», отключённый режим «Контейнеры ТМ / Товары ТМ», disabled-кнопки «Создать ТМ», PAL, MIX. Заголовки таблицы: ТМ, SKU, ШТ, Короба, Объём; пустое состояние «Транспортные места ещё не созданы». Не добавлять фиктивные строки для заполнения пространства.

Внизу «Осталось к распределению» с шестью показателями из remainingTotals. Не добавлять «Онлайн», поиск, реальные статусы обмена, сканирование и кнопки навигации браузера из картинок.

### Компоненты и данные

Одна страница в src/pages/shipment, небольшие компоненты для сводки, исходных контейнеров, панели действий, ТМ и остатков. Общие примитивы остаются в components/ui; строгая FSD, маршрутизатор и универсальная библиотека таблиц не нужны.

Один стабильный экземпляр ShipmentStore создаётся на время жизни страницы через lazy initializer и передаётся компонентам. Читающие observable-данные компоненты используют observer. Не создавать стор заново при render и не копировать его данные в отдельный React state.

Строки левой таблицы вычисляются по remainingLines, контейнерам и products, с теми же формулами, что и существующие итоги. Вычисления вне JSX, при необходимости выделить общий helper агрегации без изменения поведения стора. Все значения из моков/стора, без вшитых в JSX итогов. КМ/КА не используются на этом экране.

Формат чисел ru-RU: целые штуки/SKU/контейнеры, до 2 знаков для коробов и веса, до 4 для объёма, до 1 для процентов. Округлять только отображение, м³ обозначать корректно. Числа в таблицах выровнять вправо и использовать tabular numerals.

### Стиль и доступность

Светлый нейтральный фон, белые панели, тонкие границы, синий акцент через согласованные theme tokens, текущий Inter. Избегать декоративных крупных карточек, тяжёлых теней и визуального выделения невыбранных строк. Disabled-элементы сохраняют читаемые подписи и native disabled, не только визуальную прозрачность. Переключатели также недоступны клавиатурой; прогресс имеет доступное имя и значение.

## Risks / Trade-offs

- Много будущих действий → компактная группировка в верхней сетке, основной объём пространства отдать таблицам.
- Автоматический минимальный размер Grid растягивает страницу → minmax(0, 1fr), min-height: 0 и проверка независимой прокрутки.
- В исходных моках всего три строки → переполнение проверить временным увеличением содержимого в браузере без изменения сохранённых моков и без тестовой инфраструктуры.
- Общий нейтральный shadcn theme → синий акцент вводить согласованно, не случайными цветами отдельных кнопок.
