## Контекст

Текущий UI отгрузки состоит из заголовка страницы, сводок заказа и остатка, статуса-подсказки и рабочей области распределения с источником, действиями перемещения и назначением. Некоторые из них уже выделены в React-компоненты, но файловая структура не делает владение блоками и публичные границы импортов явными.

## Цели / Не-цели

**Цели:**

- Сделать каждый блок страницы отгрузки самостоятельным и легко находимым.
- Дать каждому независимо используемому блоку локальный `index.ts` в качестве публичного API.
- Хранить приватные детали реализации рядом с владеющим ими блоком.
- Сохранить текущее поведение UI и интерфейсы domain-store.

**Не-цели:**

- Изменение поведения распределения, структур данных или видимого пользователю контента.
- Введение архитектуры компонентов для всего репозитория или глобальных barrel-файлов.
- Переработка generic shared UI-компонентов.

## Решения

### Страница — корень композиции

`ShipmentPage` будет создавать store и располагать верхнеуровневые блоки. Детали реализации панелей не будут её ответственностью. Так страница останется единственной точкой, где видна композиция экрана.

### Локальные публичные API через `index.ts`

Директория каждого независимо используемого блока будет экспортировать публичный React-компонент и, при необходимости, типы через локальный `index.ts`. Потребители импортируют из директории, а не из приватного файла реализации.

Shipment-wide barrel не будет агрегировать экспорты. Глобальный barrel скрывает пути зависимостей, неявно расширяет публичную поверхность и повышает риск циклических импортов.

### Владение остаётся у блока

Компоненты, хелперы, константы и стили, используемые только одним блоком, остаются внутри его директории. Блок может импортировать shared UI/domain-утилиты или документированный публичный API другого блока, но не его приватные файлы.

Вынос в shared оправдан только после реального повторного использования независимыми блоками. Это предотвращает преждевременное появление универсальной директории shared.

## Риски / Компромиссы

- [Избыточная фрагментация] → Оставлять небольшие хелперы локально и не создавать папки для одного тривиального контрола.
- [Циклические зависимости через index] → Направить импорты от страницы к блокам, а из блоков — только к shared-коду или явным публичным API соседних блоков.
- [Неясное владение CSS] → Перемещать селекторы, специфичные для блока, рядом с ним; на уровне страницы оставить только раскладку и общие токены отгрузки.
