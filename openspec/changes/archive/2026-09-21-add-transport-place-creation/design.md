## Context

`ShipmentStore` уже владеет полным состоянием одного заказа: исходными контейнерами и товарами, а также формируемыми `transportPlaces` и `allocationLines`. Начальный мок содержит пустой список ТМ. Правая панель умеет показывать только пустое состояние, а «Создать ТМ» обёрнута в disabled-заготовку Dialog.

По исходному описанию процесса каждое ручное нажатие создаёт одно ТМ и делает его активным. Для прототипа состояние остаётся локальным в памяти; номера SSCC, интеграция с 1С и восстановление с сервера появятся позже.

## Goals / Non-Goals

**Goals:**

- создавать пустые ТМ непосредственно в существующем `ShipmentStore`;
- присваивать им уникальные в рамках сеанса локальные номера по порядку создания;
- хранить и изменять активное ТМ;
- отображать созданные ТМ и активное состояние в существующей таблице;
- сохранить текущие расчёты заказа, остатков и прогресса неизменными.

**Non-Goals:**

- распределение товара и автоматическое создание ТМ при первом переносе;
- удаление ТМ, `PAL`, `MIX`, SSCC и типы тары;
- Dialog подтверждения, уведомления, undo и ограничения количества ТМ;
- REST API, сохранение, восстановление состояния и тестовая инфраструктура.

## Decisions

### Один store для исходных данных и результата работы

Создание и выбор ТМ добавляются в `ShipmentStore`, а не в отдельный destination-store. Будущие распределения связывают `SourceLine` и `TransportPlace`, а остатки и прогресс вычисляются из обеих частей; единый MobX action сохранит такие изменения атомарными. Компоненты продолжают получать один стабильный экземпляр store.

### Активное ТМ — состояние рабочего сеанса

Store получает наблюдаемое `activeTransportPlaceId: string | null`. Оно не добавляется в `ShipmentData`, потому что не является частью входного снимка или сохраняемого состава ТМ. Конструктор начинает с `null`; `createTransportPlace` активирует созданное место, а `selectTransportPlace` принимает только ID существующего места.

Альтернатива — локальный React state правой панели — отклонена: активное ТМ потребуется будущим командам распределения и нескольким UI-блокам.

### Последовательная локальная нумерация

Следующий `sequence` равен максимальному существующему `sequence` плюс один, а не длине массива плюс один. Отображаемый `number` формируется как `ТМ-` и трёхзначный sequence (`ТМ-001`). Локальный технический `id` также строится из sequence и должен быть уникален в текущем store. Это детерминировано для демо и не смешивает локальный номер с будущим SSCC.

Повторное использование освободившихся номеров не предусматривается: это упростит последующее добавление удаления пустых ТМ.

### Создание без Dialog

Кнопка «Создать ТМ» напрямую вызывает команду store. Пользователь ничего не вводит и не выбирает, поэтому подтверждение не несёт полезной информации. Существующий общий компонент Dialog остаётся в UI-kit, но удаляется из этого действия.

### Представление правой таблицы

`DestinationPanel` становится `observer`, получает `ShipmentStore` через публичный API блока и отображает `transportPlaces` по `sequence`. До реализации распределения показатели SKU, штук, коробов и объёма у новых ТМ равны нулю. Активная строка имеет визуальное и доступное состояние выбора; выбор другой строки вызывает `selectTransportPlace`.

Пустое сообщение показывается только при отсутствии ТМ. Создание пустого ТМ не добавляет `AllocationLine` и не меняет исходные итоги, остатки или прогресс.

## Risks / Trade-offs

- [Локальные ID и номера позже будут заменены серверными] → держать SSCC вне `number`, а генерацию локального идентификатора изолировать в команде store.
- [Интерактивная строка таблицы может быть недоступна с клавиатуры] → использовать семантически доступный элемент выбора или добавить строке корректную клавиатурную активацию и `aria-selected`.
- [Будущее удаление может оставить пробелы в нумерации] → считать sequence монотонным и не переиспользовать старые номера.
- [Таблица пока показывает только нули] → явно ограничить change созданием пустых ТМ; расчёт состава добавить вместе с распределением.

## Migration Plan

Изменить store и правую панель без миграции данных: исходный мок остаётся пустым. При откате вернуть кнопку в disabled-состояние и статичную пустую панель; формат `ShipmentData` не требует обратного преобразования.

## Open Questions

Нет блокирующих вопросов. `PAL/MIX` и удаление пустых ТМ согласованы как следующий отдельный change.
