## Context

`ShipmentStore` уже владеет данными одного заказа, хранит `activeTransportPlaceId` и вычисляет остатки, итоги и прогресс из `SourceLine` и `AllocationLine`. Левая панель агрегирует остатки по контейнерам, правая — распределения по ТМ. Сейчас исходные строки и все пять операций переноса заблокированы.

В рамках change пользователь распределяет только весь текущий остаток выбранного контейнера. Сеть, постоянное хранение и логика КМ/КА отсутствуют; результат живёт до перезагрузки страницы.

## Goals / Non-Goals

**Goals:**

- позволить выбрать один контейнер с положительным остатком;
- атомарно распределить все его оставшиеся `SourceLine` в активное ТМ;
- сохранить ограничения количества и целостность связей `AllocationLine`;
- реактивно обновить обе панели, остатки и прогресс;
- сохранить доступное управление строкой с мыши и клавиатуры.

**Non-Goals:**

- частичное распределение и ввод количества;
- возврат из ТМ, массовые операции и режим товара;
- перенос самого объекта `PickingContainer` в состав ТМ;
- назначение конкретных КМ/КА транспортному месту;
- подтверждение операции, undo, REST API и persistence.

## Decisions

### Store owns transient source selection

`ShipmentStore` получит наблюдаемый `selectedContainerId`, отдельный от `ShipmentData`, как уже сделано для активного ТМ. Выбор строки является состоянием текущего рабочего сеанса, а не частью входных или будущих серверных данных.

Альтернатива — локальный React state в левой панели — усложнила бы доступ кнопки переноса к выбору и разделила состояние одного процесса между компонентами.

### Distribution moves the current remainder

Команда распределения использует выбранный контейнер и активное ТМ, находит его `remainingLines` с положительным остатком и переносит каждую строку целиком. Исходные `SourceLine` не изменяются: операция добавляет количество в `AllocationLine`.

Если пара `sourceLineId + transportPlaceId` уже существует, её количество увеличивается; иначе создаётся новая строка с уникальным локальным ID. Это сохраняет компактное представление и позволяет тому же механизму работать после будущих частичных возвратов. Перед изменением команда проверяет существование контейнера и ТМ и наличие положительного остатка, поэтому не создаёт частичный результат при ошибке.

### Fully distributed containers leave the source view

`containerRows` будет возвращать только контейнеры, у которых сумма текущих остатков больше нуля. Объект контейнера и исходные строки остаются в `ShipmentData`; поэтому будущий возврат положительного количества автоматически снова покажет контейнер слева.

После успешного распределения `selectedContainerId` сбрасывается, а `activeTransportPlaceId` сохраняется для следующей операции.

### Only the first transfer action becomes operational

Строки источника получают состояние выбора и клавиатурную активацию. Существующая кнопка «Переместить строку» становится обычной кнопкой и доступна только при валидном выбранном контейнере и активном ТМ. Нажатие выполняет действие сразу, без Dialog. Остальные четыре операции и переключатели режимов сохраняют текущее disabled-поведение.

### Marking data remains untouched

Для маркированных товаров на этом этапе распределяется только количество исходной строки. `MarkingCode` и `AggregationCode` не изменяются и не связываются с ТМ. Их обработка потребует отдельного сценария сканирования и отдельного change.

## Risks / Trade-offs

- [До реализации возврата операцию нельзя отменить в UI] → состояние прототипа не сохраняется и восстанавливается перезагрузкой; подтверждение намеренно не добавляется.
- [Распределение маркированного товара пока не фиксирует конкретные коды] → change явно ограничивается количественным распределением и не меняет данные КМ/КА.
- [Выбор может устареть после внешнего изменения данных] → вычисляемая доступность команды повторно проверяет существование контейнера, ТМ и положительного остатка; команда также защищает инварианты.
