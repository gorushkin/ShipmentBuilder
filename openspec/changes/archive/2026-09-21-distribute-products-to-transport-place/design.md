## Context

Левый режим «Товары» уже агрегирует положительные остатки `SourceLine` по `productId`; выбранная строка хранится как `selectedProductId`. Количественные распределения представлены `AllocationLine`, которая ссылается на конкретную исходную строку и ТМ. Правая область пока показывает только список ТМ, а кнопки работают лишь для контейнеров и возврата всего содержимого ТМ.

Первое ТМ автоматически создаётся при открытии процедуры и становится активным. Если состояние всё же не содержит активного ТМ, существующая защитная логика подготовки ТМ используется и при валидном переносе товара.

## Goals / Non-Goals

**Goals:**

- Переносить весь текущий остаток выбранного товара в активное ТМ, не теряя сведения об исходном контейнере.
- Показывать товары только активного ТМ и позволять вернуть из него весь выбранный товар.
- Сделать состояния выбора и доступность кнопок однозначными при переключении режимов и ТМ.

**Non-Goals:**

- Частичный перенос, фильтрация, массовые операции, изменение текстов кнопок, PAL/MIX.
- Сканирование, назначение, проверка или изменение КМ и КА.
- Просмотр одной сводной таблицы товаров всех ТМ, сохранение на сервере или в browser storage.

## Decisions

### Агрегированный товар раскладывается по исходным строкам

Команда переноса получает выбранный `productId`, находит все `remainingLines` этого товара и переносит полный остаток каждой строки в активное ТМ. Для пары `sourceLineId + transportPlaceId` количество добавляется к существующей `AllocationLine` либо создаётся новая.

Так сохраняется происхождение товара из контейнера и возврат не требует искусственно восстанавливать контейнеры. Альтернатива — создать одну агрегированную строку товара ТМ без `sourceLineId` — не позволяет корректно вернуть товар к источникам и ломает модель распределений.

### Товары справа ограничены активным ТМ

В сторе вводится отдельный режим правой области и ID выбранного товара ТМ. Helper агрегирует положительные `AllocationLine` активного ТМ по `productId`, отображая код, наименование, штуки и короба. Переключатель «Товары ТМ» доступен только при активном ТМ; пустое активное ТМ показывает заглушку.

Сменить ТМ можно только в режиме «Контейнеры ТМ»: пользователь возвращается к списку ТМ, выбирает цель и снова открывает «Товары ТМ». Автоматического переключения правого режима после переноса нет. Альтернатива — общий список товаров всех ТМ — отвергнута, потому что в нём нет однозначной цели переноса и возврата.

### Возврат удаляет распределения выбранного товара только из активного ТМ

Команда возврата фильтрует `AllocationLine` по активному `transportPlaceId` и `productId` исходной строки. Она удаляет все совпадающие строки, включая части товара из разных контейнеров, и не затрагивает другие товары или ТМ. После успеха сбрасывается только выбор товара ТМ.

### КМ и КА остаются данными исходного набора

Обе команды меняют только `allocationLines`. `MarkingCode` и `AggregationCode` не получают ссылок на ТМ и не изменяются; маркированный товар участвует лишь как количество. Полная обработка кодов потребует отдельного сценария сканирования.

## Risks / Trade-offs

- [Товар может происходить из нескольких контейнеров] → распределять и удалять все соответствующие `AllocationLine` по исходным строкам, а не одну агрегированную запись.
- [Выбор становится неактуальным при смене контекста] → очищать его при успешной операции, смене режима и активного ТМ.
- [Правый режим может быть открыт в пустом ТМ] → показывать явную заглушку, не блокируя сам просмотр.
