## Context

Левая панель имеет локальный переключатель «Контейнеры / Товары». После рефакторинга таблицы получают DTO-проекции из общего `ScannerWorkflowOrchestrator`, который читает `ShipmentDataStore`. Этот инкремент отвечает только за два вида отображения; scanner-workflow, выбор строк и фильтры описываются отдельно.

## Goals / Non-Goals

**Goals:**

- Переключать левую таблицу между агрегированными контейнерами и агрегированными товарами.
- Получать строки товаров только из текущего остатка заказа, не меняя исходные строки или распределения.
- Добавить ясное пустое состояние товарного режима.
- Оставить строки таблиц read-only.

**Non-Goals:**

- Не вводить фильтры по контейнеру или товару и не связывать сканирование с видом таблицы.
- Не менять семантику действий переноса.
- Не переносить товары и не добавлять persistence.

## Decisions

### Локальное UI-состояние режима

Режим источника хранится локально в левой панели и не меняет машину сканирования, фильтр или предметные данные. Управление режимом со стороны сканера не входит в этот инкремент.

Выбор строки не реализуется: после рефакторинга таблицы являются read-only, а выбор станет частью следующего workflow-инкремента.

### Агрегация по текущему остатку

Строки товарного режима строятся из `remainingLines`, группировкой по `productId`. Для каждой группы используются код и наименование из `Product`, сумма остатка в штуках, расчёт коробов через `unitsPerBox` и число уникальных контейнеров с положительным остатком. Нулевые группы исключаются, порядок — по коду товара.

Альтернатива — агрегировать исходные `sourceLines` — отклонена: она показывала бы уже распределённый товар и расходилась бы с контейнерным режимом и нижними остатками.

### Одна панель, две read-only таблицы

Переключатель остаётся контролом в заголовке панели. В зависимости от режима панель запрашивает соответствующую проекцию оркестратора. Когда список товаров пуст, вместо таблицы выводится заглушка «Все товары распределены».

Строки не выбираются и не запускают доменные команды. Кнопки переноса и фильтры не изменяются.

## Risks / Trade-offs

- [Агрегация на каждом реактивном обновлении] → Моковые данные малы; для будущих крупных заказов можно добавить вычисляемый индекс в сторе без смены внешнего поведения.
- [Наличие выбранной товарной строки без операции] → Визуальный выбор нужен как подготовка последующего инкремента; недоступные действия сохраняют явные подсказки.
