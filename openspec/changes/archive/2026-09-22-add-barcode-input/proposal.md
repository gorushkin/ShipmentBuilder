## Why

Форма формирования транспортных мест предназначена для непрерывной работы со
сканером штрихкодов, но текущий прототип принимает действия только мышью.
Нужен первый, изолированный шаг: надёжная точка приёма штрихкода, которая позже
станет входом для машины состояний и оркестратора операций.

## What Changes

- Добавить независимую UI-фичу `BarcodeInput` перед сведениями о заказе.
- Постоянно рендерить enabled и focusable форму ввода; в штатном режиме
  визуально скрывать её, не исключая из DOM.
- При нативном submit формы по `Enter` выводить нормализованное значение и
  ISO-время в технический console log. На этом этапе ввод не изменяет данные
  заказа, фильтры или распределения.
- Добавить `BarcodeInputController` для управления значением, submit, фокусом
  и представлением поля.
- Добавить кнопку и `F2` для раскрытия ручного ввода, `Esc` для возврата к
  скрытому виду; отдельная кнопка submit не требуется.
- После мышиных действий возвращать фокус на scanner input, кроме открытого
  модального диалога и другого целенаправленно редактируемого текстового поля.

## Capabilities

### New Capabilities

- `barcode-input`: Приём завершённого штрихкода через постоянно доступную
  форму, управление его видимостью и фокусом.

### Modified Capabilities

- `shipment-ui-shell`: Экран получает расположенный перед сводкой заказа
  компонент ввода штрихкода; прежний запрет на сканирование снимается только
  для технического ввода без доменных действий.

## Impact

- Затрагиваются `src/pages/shipment/shipment-page.tsx`, CSS-компоновка экрана
  и новый UI-компонент `BarcodeInput` с его контроллером.
- Используется уже установленный shadcn `Input`; новые зависимости, API,
  изменение `ShipmentStore`, state machine и оркестратор не входят в change.
