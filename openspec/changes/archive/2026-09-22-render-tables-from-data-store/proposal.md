## Why

Таблицы распределения пока отображают данные старого `ShipmentStore`, хотя новый независимый `ShipmentDataStore` уже загружается оркестратором. Нужно переключить именно табличное отображение на новый источник данных, чтобы следующий этап фильтрации и реакций строился поверх целевой архитектуры.

## What Changes

- `ScannerWorkflowOrchestrator` предоставляет проекции строк левой и правой таблиц по переданному режиму отображения.
- Табличные панели читают один общий экземпляр orchestrator без прокидывания `ShipmentStore` или `ShipmentDataStore` через props.
- Режимы «Контейнеры / Товары» и «Контейнеры ТМ / Товары ТМ» остаются локальным UI-состоянием соответствующих панелей и передаются в методы проекций.
- Таблицы показывают остатки источника либо состав транспортных мест из нового `ShipmentDataStore`; фильтрация пока не инициируется и не применяется.
- Выбор строк не запускает доменные действия: обработчики временно отключены либо ограничены техническим `console.info` с типом сущности и ID.
- Сводки и операции страницы, не относящиеся к табличному рендерингу, остаются вне этого изменения.

### Modified Capabilities

- `scanner-workflow-orchestrator`: добавить read-only методы для получения типизированных строк таблиц по режиму, используя переданный ему `ShipmentDataStore`.
- `shipment-ui-shell`: таблицы читают строки из общего экземпляра orchestrator и не используют старый `ShipmentStore`; выбор строки временно не вызывает фильтрацию или операции.
- `container-distribution`: временно отложить выбор исходного контейнера кликом по строке в новой read-only таблице.
- `transport-place-creation`: временно отложить выбор активного ТМ кликом по строке и отображать active state только если он есть в новом store.
- `transport-place-product-mode`: режимы остаются локальными и доступны для показа пустой проекции без active ТМ; клики по строкам товара пока не выбирают товар.

## Impact

- Затрагиваются композиция экземпляров страницы, `ScannerWorkflowOrchestrator` и компоненты левой/правой таблиц.
- Не меняются доменные операции `ShipmentDataStore`, алгоритмы фильтрации, сканерные переходы, старые сводки и кнопки перемещения.
- Поскольку таблицы читают orchestrator напрямую, страница и таблицы должны использовать один общий экземпляр runtime; дублирование orchestrator/store недопустимо.
