## Why

Новый scanner workflow уже синхронизирует выбор и фильтры, но переносы только логируются, а старые кнопки работают с другим store. Нужен единый исполняемый процесс для сканера и мыши с завершением операций, возвратами и вводом количества.

## What Changes

- Ввести общий каталог команд переноса/возврата и коротких командных штрихкодов.
- Добавить машине состояния выполнения, ожидания товара для возврата и количества, события завершения, ошибки и отмены.
- Исполнять операции через оркестратор и ShipmentDataStore; автоматически создавать ТМ при отсутствии активного назначения.
- Поддержать приоритет явно выбранной исходной строки перед последовательным сканированием; после успеха очищать выбор строки, сохраняя фильтр даже при пустом остатке.
- Перевести кнопки, диалог количества и показатели распределения на новый workflow и единый источник данных.
- Реализовать сначала полные переносы и возвраты, затем частичные операции в рамках того же change.

## Capabilities

### New Capabilities

- `scanner-transfer-workflow`: каталог операций, их источники, завершение и пользовательские сценарии полного и частичного распределения/возврата.

### Modified Capabilities

- `scan-machine`: исполняемые операции вместо неисполняемых intents; выбор строки и товара назначения.
- `scanner-workflow-orchestrator`: выполнение effects, подтверждение результата, проекции исходных строк и единые данные UI.
- `barcode-resolution`: полный каталог команд и отмена.
- `shipment-data-store`: явный scope строки/контейнера/товара для атомарных операций.
- `bulk-filter-transfer`: новый workflow, сохранение фильтра после массового переноса.
- `transport-place-return`: возвраты через новый workflow с сохранением source context.
- `transport-place-product-return`: полный и частичный возврат через новый workflow.
- `partial-product-quantity`: диалог как проекция awaiting-quantity с явным scope.

## Impact

ScanMachine, BarcodeResolver/adapter, ScannerWorkflowOrchestrator, ShipmentDataStore, таблицы, кнопки переноса/возврата, диалог количества, summary/progress и документация архитектуры. Старые методы ShipmentStore перестают обслуживать этот workflow; внешнее API и backend не добавляются. Количественные операции сохраняют исходные SourceLine и данные маркировки.
