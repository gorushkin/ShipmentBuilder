## Context

`BarcodeInput` уже поддерживает скрытое CSS-представление, постоянный фокус и
кнопку с подсказкой `F2`. Во время разработки его локальное состояние было
изменено на раскрытое по умолчанию. Обработчик `Esc` также вызывает отмену
workflow до того, как сворачивает раскрытый scanner input.

## Goals / Non-Goals

**Goals:**

- Восстановить скрытый стартовый вид без изменения одного и того же DOM-input.
- Сделать `F2` и `Esc` предсказуемыми для ручного ввода и сканера.
- Уточнить видимую подпись кнопки возврата без изменения команды.

**Non-Goals:**

- Не добавлять новую комбинацию клавиш, логику возврата или новый workflow
  command.
- Не менять поведение `Esc` вне раскрытого сфокусированного scanner input.

## Decisions

- Состояние `isExpanded` начинается со значения `false`. Поле остаётся в DOM,
  enabled и focusable, поэтому сканер продолжает вводить в него в скрытом виде.
- При `F2` компонент предотвращает браузерное действие, раскрывает input и
  возвращает ему фокус, если не открыт modal dialog и фокус не находится в
  другом текстовом поле. Отдельная клавиатурная комбинация не нужна: `F2` уже
  является отображённым контрактом интерфейса.
- При `Esc` из раскрытого сфокусированного scanner input обработчик сначала
  сворачивает input и завершает обработку события. Поэтому `onCancel` не
  вызывается для этого случая; прежняя отмена остаётся доступна для иных
  состояний без открытого диалога.
- Отображаемый текст `return-product` меняется на `Вернуть строку`; его
  идентификатор и обработчик команды сохраняются.

## Risks / Trade-offs

- [Функциональные клавиши работают как системные media-keys на части
  ноутбуков] → приложение сохраняет кнопку раскрытия; пользователю может
  потребоваться системная настройка Fn-клавиш.
- [Перехват `Esc` мог отменять workflow] → он ограничен только открытым и
  сфокусированным scanner input, как требует сценарий ручного ввода.
