# Design

## Context

См. proposal.md для мотивации и specs/button-shortcuts/spec.md для назначений. Button основан на Base UI; Tooltip уже есть, App задаёт задержку 300 мс. UnavailableButton оборачивает disabled-кнопку в span для подсказки. Менеджер сопоставляет event.key, точно учитывает модификаторы и разделяет сканирование и сочетания. useShortcut поддерживает accepts и политику редактирования. F2 и Escape принадлежат useBarcodeInput; печать сейчас отдельно регистрирует Ctrl+P.

## Goals / Non-Goals

**Goals:** единый контракт представления, одна регистрация на сочетание, единая проверка доступности для клика и клавиатуры, сохранение композиции Base UI через render.

**Non-Goals:** новые доменные команды, новые назначения внутри диалогов, физические клавиши или алиасы раскладок, настройка отключения одиночных букв, изменение алгоритма сканирования.

## Decisions

### 1. Button отвечает за представление; регистрация остаётся у владельца действия

Добавить опциональный `shortcut` и строковый `title` в общий Button. Из shortcut получать плашку, текст сочетания в тултипе и ARIA. Без shortcut сохранить обычную композицию Button. Владельцы действия передают одно и то же значение в Button и useShortcut, используя константу или описание действия; не дублировать строковые литералы.

Автоматическую регистрацию из Button не использовать: кнопка может быть триггером Base UI через render, а F2/Escape уже принадлежат отдельному контроллеру. Она также рискует включить disabled-заглушки и создать конфликт регистраций. Общая UI-кнопка не должна импортировать workflow или угадывать поведение события click.

### 2. Общий форматтер сочетаний

Сохранить внутренний синтаксис менеджера: `p`, `shift+d`, `ctrl+p`. Форматтер возвращает визуальную подпись и ARIA отдельно: P / p, Shift+D / Shift+d, Ctrl+P / Control+p, Meta+P / Meta+p. Прописная визуальная буква не добавляет Shift. Использовать семантический kbd с aria-hidden для декоративной плашки. Форматтер разместить в клавиатурном модуле и экспортировать через его публичный API; не добавлять альтернативную нормализацию.

Скобки внутри подписи отвергнуты: отдельная плашка визуально отделяет название действия от клавиши. Одна лишь подсказка хуже обнаруживается на рабочем экране. Для иконочных кнопок оставлять сочетание в тултипе, с явным доступным именем.

### 3. Команды страницы и актуальная доступность

Сопоставления из спецификации хранить рядом с владельцами действий. Переносы/возвраты используют существующие команды workflow; их canCommand проверяется в accepts и повторно перед вызовом. Создание ТМ использует те же ограничения snapshot/busy/waiting, что кнопка. Сброс фильтра доступен только при существующем фильтре. Новые буквенные сочетания игнорируют редактирование по умолчанию.

У будущих disabled-действий назначение только отображается; не регистрировать пустые handlers и не добавлять операции PAL/MIX. Открытие печати перевести на P. F2 и Escape оставить в useBarcodeInput и передать их значения в представление без второй регистрации; сохранить приоритет поля и очистки буфера. Блокировку диалогами и списками продолжает обеспечивать существующий механизм.

### 4. Нативные подсказки

По уточнению пользователя использовать стандартный строковый title вместо Base UI Tooltip. Button добавляет форматированное сочетание в скобках, сохраняя плашку kbd и постоянное sr-only описание с aria-describedby. Для disabled-кнопок title устанавливается на фокусируемую обёртку. UnavailableButton формирует строковое пояснение недоступности и делегирует отображение Button.

Задержку и закрытие определяет браузер. Провайдер Tooltip убран из App; общий неиспользуемый UI-примитив Tooltip остаётся в исходном виде. Реестр закрытия тултипов по Escape и его тест удалены: Escape снова полностью принадлежит существующему клавиатурному менеджеру.

### 5. Курсоры и компоновка

В общем Button задать pointer для доступного состояния и not-allowed для disabled. Текущее disabled:pointer-events-none мешает отображению курсора на самом элементе: убрать это правило или переопределить для реальной кнопки, полагаясь на нативную/Base UI блокировку действия. На обёртке недоступного Button отдельно задать not-allowed и отключить pointer-events у внутренней disabled-кнопки, чтобы наведение принимала обёртка. Проверить переносы и ширину кнопок после добавления плашек при 1440×900 и 1280×720.

## Risks / Trade-offs

- [Однобуквенные сочетания не выполняют полное требование WCAG 2.1.4 без отключения/переназначения] → Пользователь явно принял их для теста; механизм настройки вне этого изменения. Доступность семантики и тултипа не объявлять полной WCAG-сертификацией.
- [Дополнительные плашки увеличивают ширину] → Проверить заголовок и центральную панель в существующих desktop-размерах и при увеличении масштаба.
- [Изменение состояния между keydown и выполнением] → Повторная проверка доступности непосредственно перед командой.
- [Фокусируемые обёртки заглушек увеличивают число Tab-переходов] → Предоставить краткое объяснение недоступности, без роли активной кнопки или обработчика активации.

## Migration Plan

Изменение локального UI без миграции данных. Сначала добавить представление и форматтер, затем обновить назначения владельцев действий и убрать прежний Ctrl+P/ручную плашку F2. Для отката убрать новые регистрации и свойства, восстановить прежнее назначение печати. Существующие правила F2/Escape и сканирования не меняются.
