# Design

## Context

Проект использует Tailwind 4 с `@tailwindcss/vite`, shadcn/Base UI, `cn` и `cva`. В `src/index.css` уже есть `@theme inline`, светлые и тёмные переменные shadcn и базовый слой. При этом рабочая страница оформлена через 652 строки в четырёх дополнительных CSS-файлах; `App.css` содержит 182 неиспользуемые строки.

`shipment.css` дублирует часть правил шапки и переопределяет стандартные классы UI-компонентов. Локальные `--primary` и `--ring` внутри `.shipment-page` не наследуются порталами диалогов и select; `Toaster` расположен вне main. Требования компоновки и доступности остаются в `openspec/specs/shipment-ui-shell/spec.md`. Мотивация описана в proposal.md.

## Goals / Non-Goals

**Goals:**
- Сделать значения темы общими для страницы и портальных элементов.
- Удалить зависимость оформления от порядка импортов компонентного CSS.
- Сохранить текущую геометрию и все рабочие состояния интерфейса.

**Non-Goals:**
- Редизайн, новая мобильная компоновка, переключатель тем или полноценная доработка dark mode.
- Изменение данных, логики операций, клавиатурных команд или структуры доменных модулей.
- Переписывание стороннего CSS, CSS внутри SVG и генерируемого CSS сборки.
- Создание отдельного универсального дизайн-системного пакета или массовое изменение неиспользуемых UI-компонентов.

## Decisions

### 1. Один авторский CSS-файл

`src/index.css` остаётся точкой входа: импорты, `@custom-variant`, `@theme`, значения семантических переменных и минимальный `@layer base`. Остальные CSS-файлы удаляются после переноса потребителей. Не добавляем компонентные селекторы или большие наборы `@apply`: это сохранило бы прежний слой стилей под новым синтаксисом. Полное удаление CSS-входа отвергнуто, поскольку Tailwind 4 настраивает тему через CSS.

### 2. Глобальная семантическая тема

Существующие роли `background`, `foreground`, `card`, `popover`, `primary`, `primary-foreground`, `border`, `input`, `ring`, `secondary`, `muted` и `accent` согласуются с текущей палитрой. Синий primary `#245ad5` переносится с main в глобальную светлую тему. `--color-*` aliases остаются в `@theme inline`, значения находятся в `:root` и существующем `.dark`.

Добавляются только используемые роли: success, warning, info, selection и selection-hover; отдельные фоновые/foreground-роли добавляются, когда действительно нужны. Совпадающие роли могут ссылаться на primary/destructive. Радиусы, типографика и тени становятся theme variables только при повторном использовании. Имеющиеся токены shadcn не удаляются вслепую; dark definitions сохраняются согласованными с добавленными aliases без обещания нового тёмного оформления.

Локальные сетки, размеры колонок и разовые значения остаются arbitrary values в JSX. Не создаём токен для каждого числа и не заменяем точные цвета похожими стандартными оттенками: геометрия и палитра страницы являются исходной точкой. Глобальная тема намеренно делает синий акцент одинаковым в диалогах, select и уведомлениях; это единственное ожидаемое согласование оформления за пределами переноса правил.

### 3. Классы располагаются у владельца элемента

Обычная геометрия переносится на элементы JSX. Для состояний используются `disabled:`, `aria-disabled:`, `focus-visible:`, `data-[active=true]:`, `group-has-*` и комбинации вариантов. Статусы barcode и history задаются полными строками в типизированных словарях или `cva`; динамическая сборка имён utilities запрещена.

Повторяющиеся стили четырёх типов строк таблицы оформляются локальным общим набором классов; дополнительные React-обёртки вводятся только при наличии общей структуры. Не переносим весь stylesheet в один объект строк. Существующие `cn` и `cva` достаточны, новая библиотека не нужна.

### 4. Настройка составных UI-компонентов

Передаваемый `className` и доступные slot-компоненты используются прежде всего. Если внутренний элемент недоступен, допустим локальный arbitrary variant по стабильному `data-slot`. Для Table при необходимости добавляется необязательная настройка класса контейнера, сохраняющая прежнее поведение по умолчанию: панель владеет прокруткой, внутренний table-container имеет overflow-visible. Не меняем все Table глобально ради страницы отгрузки.

У Progress сначала используются доступные классы и slot-селекторы; изменение публичного API требуется только если это делает настройку проще. Размеры SVG задаются через `size-*`, чтобы согласоваться с существующими вариантами Button. Переопределения disabled, aria-disabled и обёртки с подсказкой проверяются отдельно, не полагаясь на порядок слов в className.

### 5. Сохранение каскада и адаптации

До переноса фиксируется фактически действующее оформление, включая дублирующие правила. При конфликте источников исходной точкой служит computed style, а не первое найденное объявление. Сохраняются breakpoint 1300px, минимальная ширина 1120px, минимальная высота 600px и строки сетки страницы. Точное условие `max-width: 1300px` сохраняется произвольным media variant при необходимости; переход на другую границу или стандартный xl не входит в задачу.

## Risks / Trade-offs

- [Потеря переопределений после удаления обычного CSS] → Переносить компоненты группами; проверять computed styles и итоговые классы после `cn`, особенно Button и Badge.
- [Вторая область прокрутки ломает sticky headers] → Явно настроить table-container и проверить обе панели с переполнением.
- [Длинные className и дубли строк] → Использовать общие наборы для повторяющихся паттернов и варианты `cva`, сохраняя локальную раскладку рядом с JSX.
- [Незаметная потеря цветов статусов] → Проверить success, warning, error, info, processing и disabled; полные классы должны обнаруживаться в production build.
- [Тема порталов меняет акценты вне main] → Проверить все диалоги, select и уведомления; согласование с синим primary допускается, прочие изменения требуют коррекции.
- [Новая роль темы неправильно классифицируется `cn`] → Проверить объединение конфликтующих классов для новых цветов/типографики и при необходимости уточнить название или настройку merger.

## Migration Plan

1. Снять исходные виды 1440×900 и 1280×720, проверить 1299/1300/1301px и состояния компонентов.
2. Согласовать глобальные токены, сохранив локальные CSS до переноса их потребителей.
3. Перенести шапку, barcode, сводки, историю и рабочую область; устранить дубли и настроить внутренние slots.
4. Удалить пять CSS-файлов и их импорты, убрать остаточные служебные классы, если они больше не нужны.
5. Выполнить production build, lint, format check, существующие тесты и проверку в браузере. Новые тесты, проверяющие только строки className, не нужны.

Изменение не требует миграции данных. При откате вернуть JSX, UI API и глобальную тему вместе с удалёнными CSS-файлами одним обратным изменением.
