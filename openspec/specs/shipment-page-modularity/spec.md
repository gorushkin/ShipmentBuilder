# Модульность страницы отгрузки

## Purpose

Определяет границы владения UI-блоками, их публичные API и правила импортов на странице отгрузки.

## Requirements

### Requirement: Страница отгрузки состоит из самостоятельно владеемых UI-блоков
Страница отгрузки ДОЛЖНА (MUST) компоновать самостоятельно владеемые UI-блоки для заголовка, сводки заказа, статуса распределения, рабочей области распределения и сводки остатка. Каждый блок ДОЛЖЕН (MUST) хранить компоненты и хелперы, используемые только им, в собственной директории.

#### Scenario: Блок получает внутреннюю деталь реализации
- **КОГДА** компонент или хелпер используется только одним блоком страницы отгрузки
- **ТОГДА** он расположен в директории этого блока, а не в корне страницы или несвязанном блоке

### Requirement: Блоки предоставляют явные локальные публичные API
Каждый блок страницы отгрузки, используемый за пределами собственной директории, ДОЛЖЕН (MUST) экспортировать публичный компонент и необходимые публичные типы из локального файла `index.ts`. Потребители ДОЛЖНЫ (MUST) импортировать блок через этот локальный публичный API.

#### Scenario: Корень композиции отображает блок
- **КОГДА** `ShipmentPage` импортирует верхнеуровневый блок
- **ТОГДА** она импортирует блок из публичного API `index.ts` директории блока

### Requirement: Блоки отгрузки соблюдают границы импортов
Блок страницы отгрузки ДОЛЖЕН (MUST) импортировать только shared-код или явно экспортированный публичный API другого блока. Функциональность отгрузки НЕ ДОЛЖНА (MUST NOT) предоставлять глобальный barrel-файл, реэкспортирующий все блоки.

#### Scenario: Блоку нужна функциональность другого блока
- **КОГДА** блок зависит от публичного компонента или типа другого блока
- **ТОГДА** он импортирует из точки входа директории этого блока, а не из приватного файла реализации

#### Scenario: Потребителю нужны UI-блоки отгрузки
- **КОГДА** потребитель импортирует блок страницы отгрузки
- **ТОГДА** он импортирует точку входа конкретного блока, а не entrypoint с агрегацией всей функциональности
