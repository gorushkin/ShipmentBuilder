# Клавиатурный ввод

`KeyboardManager` — независимый от React и предметной области приёмник клавиш. `connectKeyboard(manager, window)` подключает одну пару глобальных слушателей и возвращает идемпотентную функцию отключения. На одно окно допустимо только одно подключение.

```ts
const remove = keyboard.register({
  shortcut: 'ctrl+a',
  whenEditing: 'ignore',
  handler: selectAll,
})
const removeScanner = keyboard.onSequence((value) => adapter.submit(value))
const release = keyboard.suspend()
release()
remove()
removeScanner()
```

Сочетание фиксируется на нажатии основной клавиши и выполняется после отпускания всех его клавиш. Модификаторы сопоставляются точно, регистр названия клавиши игнорируется. Левая и правая клавиши модификатора отслеживаются отдельно. Повторы перехваченного нажатия поглощаются, не добавляют символы и не продлевают ожидание.

Вне редактирования печатные символы собираются с интервалом до 200 мс. Одиночный хоткей ждёт и тайм-аут, и отпускание; незавершённая строка из нескольких символов отбрасывается. Enter/Tab фиксируют строку, которая отправляется после отпускания завершителя; регистр исходной строки сохраняется. Escape очищает буфер без вызова команды. Параметр `timeoutMs` настраивается при создании менеджера; сканер должен укладываться в выбранный интервал.

`whenEditing: 'allow'` разрешает сочетание в поле редактирования, но не включает буфер сканера. Необязательный `accepts(context)` дополнительно ограничивает регистрацию, например, одним конкретным полем. По умолчанию редактируемые элементы исключены. Принятый символ перехватывается сразу; воспроизведение штатного поведения после тайм-аута не предусмотрено.

`suspend()` возвращает независимое идемпотентное освобождение блокировки. До освобождения всех блокировок не работают даже сочетания с `allow`. Общий экземпляр `keyboard` из `runtime.ts` и `useKeyboardSuspension` подключают блокировки всплывающих элементов; открытие блокирует синхронно, закрытие и размонтирование освобождают. Диалоги и списки общего интерфейса уже используют этот механизм. Новое меню должно использовать тот же механизм.

Буфер и ожидания очищаются при приостановке, потере фокуса окна, начале композиции и отключении. Вход в редактирование отменяет запрещённые там действия. Обработчики могут возвращать обещания: последующие события не ждут их завершения. Ошибки отправляются в `onError`; исключение самого уведомления диагностируется безопасным резервным путём.

Раскрытием ручной формы управляет `BarcodeInputController`; его создание и регистрацию в менеджере инкапсулирует хук `useBarcodeInput` в модуле ручного ввода. Страница подключает только глобальный менеджер. Кнопка и зарегистрированный хоткей вызывают его методы; форма не регистрирует глобальные клавиши и не возвращает себе фокус после чужих действий.

Общий экземпляр экспортируется из модуля как `keyboard`. Его импорт не подключает DOM-слушатели: страница подключает и отключает их своим эффектом. Класс остаётся доступен для изолированных экземпляров в тестах.

## Регистрация из React

```tsx
useShortcut('ctrl+p', () => setOpen(true))
useShortcut('F2', toggleInput, { whenEditing: 'allow', accepts: manualInputOrPage })
```

Хук вызывается в теле компонента. Регистрация создаётся в эффекте и удаляется при размонтировании. Обработчик и условие `accepts` используют актуальные значения последнего завершённого рендера, без ручного `useCallback` и без перерегистрации из-за новой функции. Смена нормализованного сочетания или политики редактирования заменяет регистрацию. Два компонента с одинаковым сочетанием по-прежнему считаются конфликтом; ссылка на функцию не определяет владельца.

## Подсказки кнопок и назначения страницы

`formatShortcut(value)` возвращает видимую подпись и значение ARIA отдельно:
`ctrl+p` → `{ label: 'Ctrl+P', aria: 'Control+p' }`. Видимая прописная буква
не означает Shift. Сопоставление остаётся по `event.key`: латинская `p` не
совпадает с кириллической `з`; алиасы раскладок и настройки переназначения пока
не предусмотрены. Однобуквенные сочетания используются для тестового этапа.

Общий `Button` принимает `shortcut` и необязательное строковое описание `title`:

```tsx
const shortcut = shipmentShortcuts.printReports
useShortcut(shortcut, openReports, { accepts: () => !open })
return (
  <Button shortcut={shortcut} title="Открыть выбор отчета для печати" onClick={openReports}>
    Печать
  </Button>
)
```

`Button` отвечает за плашку, `aria-keyshortcuts` и постоянное доступное описание,
но не регистрирует команду. Владелец действия передаёт одно значение в хук и
кнопку. Проверка доступности нужна при приёме сочетания и перед исполнением.
Недоступная кнопка сохраняет disabled и показывает описание через фокусируемую
обёртку; будущие действия не получают активирующих обработчиков.

Подсказка использует нативный `title`: к описанию автоматически добавляется
сочетание в скобках, например «Открыть выбор отчета для печати (P)».
Для disabled-кнопки title устанавливается на фокусируемую обёртку.
Задержку, размещение и закрытие подсказки определяет браузер. Описание действия
и сочетания доступно через `aria-describedby` независимо от нативной подсказки.
Специальной обработки Escape для подсказок нет. У доступных кнопок курсор
pointer, у disabled-кнопок и их обёрток — not-allowed.

Назначения основного экрана хранятся в `pages/shipment/shared/shortcuts.ts`;
существующие F2/Escape — в `barcodeShortcuts`. Диалоги и Select не получают
новых назначений; открытие диалога внешней кнопкой входит в этот набор.

| Кнопка                                         | Сочетание   |
| ---------------------------------------------- | ----------- |
| Отправка ТМ в 1С                               | S           |
| Получить SSCC                                  | C           |
| Получить маркировки                            | L           |
| Повторная отправка                             | R           |
| Печать этикетки ТМ                             | T           |
| Открыть печать отчета                          | P           |
| Создать ТМ                                     | N           |
| Переместить строку / вернуть строку            | D / Shift+D |
| Переместить всё по фильтру / вернуть всё из ТМ | A / Shift+A |
| Переместить количество / вернуть количество    | Q / Shift+Q |
| PAL / MIX (недоступны)                         | B / M       |
| Сбросить фильтр                                | X           |
| Развернуть / свернуть ввод                     | F2          |
| Отмена операции                                | Escape      |

F2 и Escape сохраняют единственного владельца в `useBarcodeInput`. Escape
в поле сначала сворачивает ручной ввод; вне поля вызывает существующую отмену.
При непустом буфере сканирования Escape очищает буфер без отмены workflow.

Настройки команд теперь загружаются из внешнего `commands.yaml` перед рендером.
Названия, описания и сочетания редактируются в этом файле; подробнее см.
[command-config](../command-config/README.md). `shipmentShortcuts` и
`barcodeShortcuts` читают значения из загруженной конфигурации.
